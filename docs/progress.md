## Phase 2 — Data model + synthetic dataset (2026-10-28)

### Done
- SQLAlchemy models (`app/models.py`): skills + synonyms, occupations + occupation_skills,
  courses + course_skills, candidates + candidate_skills + candidate_skill_assessments, jobs +
  job_skills. 11 tables total.
- Alembic wired to models (`alembic/env.py` imports `Base.metadata`), initial migration
  autogenerated and applied against live Postgres — verified via `\dt` (11 tables + alembic_version).
- `docker-compose.yml`: exposed Postgres port 5432 to host for local tooling (Alembic, generator
  scripts) to connect directly.
- Deterministic synthetic data generator (`app/generate_synthetic_data.py`, seed=42): 2000
  candidates, 1000 jobs, 150 occupations, 100 courses, 64 curated skills.
- **Verified reproducibility**: hashed candidates table (full_name+email) before/after a repeat
  run against a freshly reset schema — identical MD5 both times.
- **Verified intentional imperfections** match target rates: missing occupation 5.05% (target
  ~5%), missing candidate salary 15.25% (target ~15%), missing job salary 8.9% (target ~10%).
- `docs/data-model.md` written: full schema reference, the "not recorded vs. assessed absent"
  design rationale, measured dataset counts, known limitations.
- Assumption A4 resolved and updated in `docs/assumptions-register.md` (deviated from "~300
  skills" placeholder in favor of 64 curated, meaningful skill names — documented reasoning).

### Known limitations carried forward (see data-model.md)
- No duplicate-candidate/duplicate-job detection yet.
- No candidate qualifications/certifications table yet (needed before full Use Case A/B scoring).
- No interaction/application history table (deferred unless collaborative filtering is pursued).
- `job_skills` derived from occupation profile, not from parsing `description_raw` — free-text
  skill extraction (Use Case C) is a separate future pipeline.

### Next
- Phase 2 follow-up (optional, before Phase 3): data-quality checks module (duplicate detection,
  identifier validation, missing-value report) and a data dictionary.
- Phase 3: matching engine MVP — deterministic skill extraction/normalization, candidate-job
  scoring, eligibility constraints, ranking, skill-gap calculation, course recommendations.
